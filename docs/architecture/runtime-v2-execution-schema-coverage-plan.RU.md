## Порядок работы и связь с требованиями

1. **execution_validation.go: 39 непокрытых операторов.** Дополнить проверки
   публичных Build/Parse по ES07–ES19: неверные и чрезмерные исходные значения
   во всех коллекциях, типизированных путях и ссылках; повторные, неверные
   и неиспользуемые привязки; перестановка нескольких источников/служб;
   отсутствие цели контейнера базы; правила локального исполняемого файла,
   рабочего каталога и назначения подключений; корни образа Windows и
   сокетов/файлов служб; несовместимый транспорт и пустые выбранные база/пользователь;
   лишние поля вариантов текста; превышение длины при слиянии литералов.
   Каждый пример изолирует отказ и проверяет ошибку, нулевой результат
   и отсутствие утечки. Прямого вызова внутренних проверок ради недостижимой
   ветви не будет.
2. **execution_value.go: 28 непокрытых операторов.** Дополнить ES15–ES20:
   отсутствующие и неверно типизированные вложенные значения; флаг файла yes/no
   и запрещённый признак выполнения дерева; неверные права и поля подключений;
   разделение полей аутентификации/значимого секрета и неверное восстановление
   ссылки; неизвестное верхнеуровневое поле при том же числе полей;
   ограниченные примеры превышения числа узлов и байтов. Различать отказ
   отдельного публичного конструктора и превышение суммы по всем полям.
   Parse должен отклонять чрезмерные общеканонические структуры до обхода их
   смысла; байты и контрольные суммы остаются корректными. Проверять через
   публичные Build/Parse, не искусственно внедрённые ошибки кодировщика.
3. **execution.go: три непокрытых оператора.** Превышения итоговых ограничений
   должны проверить передачу ошибки executionFields. Ветви отказа AddIdentityField
   и итогового Build сопоставить с фиксированной семипольной схемой и проверенными
   значениями. Только при доказанной недостижимости по документированному
   инварианту упростить их обработку, пояснив инвариант в комментариях.
   Перехватчики рабочего кода и подделка закрытого состояния не добавляются.
   Так же проверить необходимость повторного построения уже корректной
   неизменяемой ссылки на секрет до предложения убрать невозможный отказ.
4. **canonical_value_inspect_v1.go: один непокрытый оператор.** Минимум уже
   достигнут. Сопоставить запасную ветвь неизвестного вида узла с инвариантом
   закрытых проверенных значений. Оставить её как пояснённую защиту либо упростить
   только при отсутствии достижимого требования. Не подменять внутренности
   ради показателя покрытия.
5. Повторить полный набор, точные проверки покрытия файлов/нового кода/модуля,
   независимые эталоны, внешнего потребителя и три цели случайного поиска.
   Согласованный поиск гонок выполняется в Linux CI; локальный Windows-запуск
   пока останавливается при запуске настроенного C-компилятора cgo, не на
   обнаруженной гонке. Получить новый подробный отчёт до предложения ещё
   одного прохода. Если обязательный порог 95% всё ещё не достигнут,
   запросить новое разрешение, а не продолжать итерацию незаметно.

Новых значимых требований из этих пробелов пока не выявлено. Если они
обнаружатся, сначала описать и согласовать дизайн, затем проверять тестами.
Для удаления кода требуется указанное доказательство; отсутствие покрытия
само по себе им не является. Прежние кодирование, области хеширования
и отдельный выпуск #151 не меняются. Завершение задачи и дорожной карты
не отмечается до прохождения обязательных проверок.

## Проверка инвариантов в согласованном проходе

Получить ненулевую закрытую SecretReference можно только её публичным
конструктором; данные неизменяемы. После Valid и дополнительных проверок
исходных размеров/NUL повторное построение не могло отказать и не проверяло
нового требования. Копирование значения в новый указатель сохраняет владение
данными без недостижимой ветви отказа.

Конструктор дерева выдаёт ровно primitive и шесть защищённых значений с
фиксированными допустимыми именами и видами. Ошибки канонического построения
и суммарные ограничения проверены до возвращения полей. Новый локальный
конструктор расширения не может быть нулевым/завершённым, получить неизвестное,
повторное или неверно типизированное поле либо пропустить обязательное.
Обработка отказов обёртки поля и AddIdentityField/итогового Build упрощена
только на основании этих предпосылок. Проверки схемы и независимых эталонов
не менялись и сохраняют контроль фиксированного набора.

Запасная ветвь неизвестного вида узла при чтении сохранена как защитная:
через закрытые публичные значения она недостижима, а файл уже покрыт выше 95%.

## Исправления после ревью PR

Позднее реализация опубликована в
[PR #152](https://github.com/kimak-irmagi/sqlrs/pull/152). Его первый коммит
`fc808d0` прошёл [все 15 задач CI](https://github.com/kimak-irmagi/sqlrs/actions/runs/38878043249),
включая поиск гонок в Linux, случайные входы, чистого потребителя и три ОС.
Это снимает ограничение прежнего локального отчёта, но не заменяет выпуск #151.

Ревью кода выявило два пробела в проверках: для STALE/UNKNOWN использовались
одинаковые прежняя и новая идентичности, а ES05 не проверял отдельно влияние
всех смысловых параметров. В исправленных тестах различаются отпечатки и
поколения подтверждающих данных; проверяются возвращённый результат, аргумент
Store и повторно прочитанная запись. Добавлены пары допустимых входов для
пропущенных параметров среды, вызова, источников, подключений, сервисов и
секретов: обе идентичности должны читаться и иметь разные канонические байты
и отпечатки. Производственный API и кодирование не меняются, тесты не ослаблены.
Документы теперь различают готовую реализацию в PR, приёмку и выпуск.
Итоговая приёмка и подтверждение CI всегда относятся к последнему коммиту PR.

Исправленные тесты прошли полный локальный набор Go и go vet. Также прошли
все 12 проверок Node и три независимые проверки эталонов/набора соответствия.
Свежий отчёт сохранил 648/652 (99,39%) для нового производственного кода и
4948/5175 (95,61%) для модуля; каждый новый производственный файл по-прежнему
покрыт выше 95%. Это локальные результаты, не утверждение, что коммит
исправлений уже прошёл CI.
