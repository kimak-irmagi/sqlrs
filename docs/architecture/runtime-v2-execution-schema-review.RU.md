# Схема выполнения: исправления и повторный разбор дизайна

Дата: 16 октября 2026 года. Проверялся проект API и структуры #150,
не реализация. Разбор выполнил тот же агент Codex, это не независимое ревью.
Запуск тестов и покрытие не заявляются. Сценарии ниже — проверка дизайна,
а не утверждённый перечень будущих тестов.

## Исходные замечания и исправления

## Второй проход: дополнительные случаи, найденные и исправленные

1. Проверка только перед выполнением обходится при попадании в кэш. Теперь
   допустимость проверяется до выбора готового состояния и повторно
   перед публикацией или общим воспроизведением.
2. Полный последующий шаг мог сделать потомка неполного состояния повторно
   используемым. Ограничение сохраняется по цепочке и после смены владельца;
   новая допустимая основа требует отдельной полной проверки.
3. Входные структуры с признаком варианта могли содержать проигнорированные
   лишние поля. Построение и чтение их отклоняют. Прежние указатели на команды
   с неоднозначным наследованием убраны.
4. Значения среды из образа могли копироваться как известные секретные литералы.
   Для них обязательна такая же классификация, как для проектных значений.
5. Точный предварительный расчёт канонического размера мог потребовать второй
   реализации кодирования. Теперь исходные ограничения предшествуют выделению
   памяти, а итоговые суммы проверяются через публичные узлы и
   NodeCount/EncodedSize без нового кодировщика.
6. Обычная локальная сборка иначе могла использовать неизвестные сетевые связи
   под видом изолированной. Явный режим local-context разрешён только
   host-executable и не допускает полного/общего повторно используемого профиля.

## Границы и последующие обязанности реализации

- Три операции используют прежний канонический результат. Семь полей новой
  схемы не меняют опубликованные схемы или записи кэша. Чтение дерева
  не меняет байты и области хеширования.
- Build/Parse не обращаются к источникам, реестру образов, процессам, файлам
  и базе. Ссылка на источник не считается доказательством; проверка полного
  описания и поддержка его схемы обязательны на границе владельца источника.
- Профили аутентификации, пути и изоляция конкретной ОС должны быть известны
  и приняты исполнителем. Неизвестная реализация отклоняется до изменений.
- Ограничения повторного использования, их сохранение по цепочке и после сбоя
  должны быть реализованы потребителем до включения рабочего профиля.
  Они не выдаются за готовый код библиотеки. После согласования API и затем
  перечня тестов реализация должна подтвердить договор проверками.

Итог повторного разбора: новых блокирующих замечаний в уточнённых границах
не обнаружено. Это не приёмка функциональности, не доказательство работы
поставщика и не обещание устранить все риски дизайна. После разбора @evilguest
утвердил исправленные API и структуру 16 октября 2026 года. Следующий шаг —
[перечень тестов](runtime-v2-execution-schema-tests.RU.md), отдельно утверждённый
в тот же день. Тесты предшествуют реализации; это не результат их запуска.
