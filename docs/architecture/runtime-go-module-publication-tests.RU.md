# Выпуск Runtime Go: согласованные проверки

Статус: перечень и подробный [договор](runtime-go-module-publication.RU.md)
согласованы @evilguest 16 октября 2026 года, включая точечную замену устаревших
ожиданий существующих тестов ниже. Локальные результаты приведены отдельно;
настоящего выпуска пока нет. Прежние тесты Go, эталоны и пороги покрытия сохраняются.

| ID | Необходимое подтверждение |
| --- | --- |
| MP01 | Режимы, значения по умолчанию, точная грамматика версии/S/кандидата; неверные ссылки, сокращения, описание, источник запуска и сочетания параметров отклоняются до записи. Границы UTF-8: описание 16 КиБ, полный текст 20 КиБ, готовый JSON 128 КиБ; экранирование, управляющие и многобайтовые символы, служебное окончание, повторы и наследуемое описание. Синтаксис оболочки/Actions остаётся данными. |
| MP02 | Точные принадлежность S к main и CI после слияния, отсутствующие/неуспешные/незавершённые/отменённые/чужие результаты, страницы и ошибки. H != S работает без новых скриптов/описания в S. Сломанный проверяющий скрипт S и исправленный H доказывают восстановление инструментария: алгоритмы из H, поиск Git явно в S; код/тесты Go, потребитель, манифест и эталоны остаются из S. Подмена копии обнаруживается. |
| MP03 | Отклоняются отсутствие защиты тегов, выключенные/неполные правила и иное пространство имён. Только GITHUB_TOKEN получает contents:write; нет замены на личный токен/приложение и повторного запуска старого процесса. Отказ прав при создании тега/выпуска явно останавливает процесс: без другой цели/токена и предположения, что validate проверяет настоящую запись. Задачи публикации не исполняют скрипты S; задачи исходников не получают её учётные данные. Прежние и продуктовые выпуски защищены. Подставные ответы не подтверждают реальные права. |
| MP04 | До публичного тега проверены исходники, кандидат, описание, размеры и существующее состояние; затем черновик, совпадающие файлы, публикация, публичная проверка. Черновик не скрывает тег Go. Независимые ожидаемые примеры проверяют описание/происхождение. Явное make_latest=false сохраняет последний выпуск продукта. |
| MP05 | Все страницы выпусков и файлов читаются с видимостью черновиков; публичного поиска по тегу и 404 недостаточно. Отклоняются скрытые/повторные выпуски, неполная видимость, конфликт S/описания/полей, неизвестные/неверные/конфликтующие файлы и ошибки доступа/ограничений/связи. 404 при записи — ошибка. Нет принудительной замены, удаления, перезаписи или создания после неоднозначной ошибки чтения. |
| MP06 | Повтор после каждой записи и потери ответа: ничего нет, только тег, совпадающий черновик без/с тегом, каждый недостающий файл, полный/неполный опубликованный выпуск, ошибка публичной проверки. Черновики продолжаются, опубликованное только проверяется; конфликты запрещают дальнейшую запись. Конкурентный конфликт требует полного повторного чтения. Активная попытка не отменяется; замена ожидающей не означает строгую очередь. |
| MP07 | verify-candidate в текущем запуске полностью проверяет опубликованного кандидата с теми же S/семейством: предварительный выпуск, описание, тег, файлы, публичные суммы, отзыв и чистый потребитель. Отсутствующий/неопубликованный/неверный/неуспешный кандидат блокирует запись. Окончательный выпуск обязательно зависит от успеха этой задачи: старый отчёт или успешный прошлый запуск не заменяют пропущенную/отменённую текущую проверку. Загрузки артефактов и зависимости от срока хранения нет. |
| MP08 | Окончательное описание в точности наследуется от проверенного кандидата; отдельное описание и неверный/отсутствующий candidate_version отклоняются. Тег и название различаются, S — нет. Суммы версий проверяются отдельно, не на равенство. H может быть новее S; новый файл/коммит под версию не нужен. validate и verify окончательной версии также перепроверяют кандидата. |
| MP09 | verify не получает учётные данные публикации и средство записи, не создаёт/меняет тег, выпуск или файлы; проверяет публичный результат. После исправления инструментария новый H проверяет прежний S без прошлых артефактов и перемещения тега. validate проверяет исходники, для окончательной версии — также кандидата, не публикуя отсутствующую целевую версию. |
| MP10 | Публичная загрузка проверяет точные версию/тег/S/модуль, непустые корректные суммы модуля/go.mod, отсутствие replace/go.work/соседних исходников, ограниченное ожидание и прежнего потребителя. Ошибка сумм, происхождения, описания или потребителя запрещает приёмку и окончательный выпуск даже после публичного тега; нет заявления об успехе или отката. |
| MP11 | Отчёт связывает операцию/версию/тег, S/H, запуск/попытку, хеш описания, суммы и результаты проверок. При ошибке виден неуспешный этап; успех записывается только для пройденных этапов. Приёмка требует успеха всего процесса, но отчёты не разрешают другие запуски. Диагностика сохраняется по попыткам; токены и описание не печатаются в ошибках, текст не дублируется в JSON, хранение артефактов не влияет на выпуск. |
| MP12 | Точечно заменяются устаревшие ожидания исходного описания/verify_published/события тега, остальные проверки качества сохраняются. Проверяется поведение связей процесса: неверные копия/корень, исполнение S с правами публикации, пропущенная зависимость, неверные права, неявное создание тега/выпуска, смена последнего выпуска продукта и порядок записи. Наличия названий команд в YAML недостаточно. |

Правила, состояния и API проверяются на локальных репозиториях и подставных
ответах GitHub, без настоящих публикаций и учётных данных. Подставной успех
не доказывает публикацию модуля. Нужен подробный построчный отчёт и минимум
95% покрытия нового помощника; прежние пороги файлов и модуля Runtime Go
сохраняются. Дополнительные проходы покрытия требуют прежнего согласования.

После ревью реализации и CI приёмка #151 всё равно требует двух настоящих
успешных выпусков v0.6.0-rc.1 и v0.6.0 на
согласованном S (bf161c7cb6bf54b1ae6f8614e452963a5ddad36f, явно выбранном
после отказа прав при создании ссылки на первоначальный коммит),
через GITHUB_TOKEN, с публичным прокси, базой контрольных
сумм и внешним потребителем. Тесты не создают временные публичные теги.
Слияние автоматизации не закрывает #151.

Первый согласованный настоящий выпуск кандидата проверяет права платформы;
пробные теги и режим пробной проверки прав API не предполагаются. Явное создание
тега предшествует выпуску по существующему тегу без target_commitish. Тесты
запрещают неявное создание тега и замену способа доступа; ошибка точно описывает
состояние частичной публикации.

Пользователь согласовал замену прежних ожиданий RELEASE-version.md в исходниках
и verify_published/события тега правилами этого документа. Точечная замена
реализована; остальные требования качества и прежние описания выпусков сохранены.

## Локальные результаты реализации (16 октября 2026 года)

### Согласованные проверки запаздывающих ответов

Ответы API должны быть отдельными снимками. Независимо задержать появление
черновика в списке, файлов — в их списке, смену признака черновика и поиск
опубликованного выпуска. Проверить: ровно один черновик, одна загрузка каждого
файла, одна публикация; полученный ID закреплён. Также проверить продолжение
прежнего черновика, исчезновение уже замеченных файлов, конфликт полей или ID
во время задержки, неверный успешный ответ создания, потерю ответа записи
при запаздывающем списке и состояние, которое так и не обновляется. Результат —
либо правильные байты, либо остановка без дубликатов и перезаписи. Ответ 409/422
без подтверждённого продвижения не разрешает повторить запись. Проверить
настоящий путь publish в CLI: итоговый отчёт не начинает новый поиск без ID.
Прежние проверки потери ответа и конфликтов сохраняются.

Совместно запущены правила публикации, CLI, связи задач workflow и прежние
проверки покрытия, происхождения и эталонов: 43 теста, 42 успешны, ошибок нет,
одна существующая проверка символических ссылок пропущена из-за ограничений
Windows. В Linux CI она сохранена без изменений. Покрытие строк нового
инструментария — 99,66%: правила 99,58%, CLI 100%; покрытие функций — 100%.
Не покрыта только строка ошибки исчерпания ограниченного числа страниц API.
Получен построчный отчёт LCOV; обычный CI требует минимум 95% и сохраняет отчёт.

Это подтверждение локальной работы автоматизации, не нового выпуска или прав
записи GitHub. Теги, выпуски и настройки не менялись; код Go библиотеки также
не менялся. Для настоящих кандидата и окончательной версии ещё требуются
проверки исходников, Go, гонок, случайных входов и обоих видов внешнего потребителя.
