## Точный контракт транспорта и наблюдений

Runtime явно передаёт `SQLRS_CAPTURE_RESULT=same-exec-v1`; отсутствующее/пустое
значение сохраняет прежний прямой запуск помощника. Неизвестный режим отклоняется
до ребёнка. `serve`/`probe-prune` по-прежнему не запускают SQL. Актуальные байты/
digest/config/readiness помощника закрепляют возможность; старые факты не меняются.

Двоичный stdout имеет ровно следующий порядок (LF в заголовках, без неявного
разделителя после данных):

```text
sqlrs-lb-result-v1\n
manifest <N>\n<ровно N байтов>
stdout <N>\n<ровно N байтов>
stderr <N>\n<ровно N байтов>
detail <N>\n<ровно N байтов>
sqlrs-lb-result-end-v1 idle none\n
```

Единственный другой footer — `sqlrs-lb-result-end-v1 idle absent\n`, требующий
точного сохранённого разрешения prune и настоящего отсутствия прежнего пути.
Без разрешения обязателен `none`. Root-помощник проверяет отсутствие ребёнка
UID1001 до конверта и после записи потоков/до detail+footer. Манифест или строка
такого вида, напечатанная ребёнком, доказательством не являются.

Длины — канонические беззнаковые ASCII decimal: ноль только `0`, без знака,
ведущих нулей, иных пробелов и переполнения. Ровно четыре фиксированных поля,
без произвольных путей/порядка/дубликатов/хвостовых байтов. Manifest <=8192,
каждый поток <=допущенного лимита (1..64 MiB), detail <=4096, строка заголовка
<=64, весь конверт <=`2*limit + 8192 + 4096 + 256`. Проверять до среза/выделения
по заявленной длине. Прежняя проверка manifest/identity/EOF/длин/хешей сохраняется.

Файлы записаны/сброшены прежним устойчивым протоколом до конверта. Только полный
транспорт возвращает exit0; код ребёнка 0..255, включая известную ошибку 7, берётся
из проверенного манифеста. Ошибка транспорта/квота/отмена/неполный footer/другой
родитель/живой ребёнок не дают capture/receipt, данные сверки сохраняются. Нет
автоматического перечитывания или повтора SQL. Явное независимое чтение файлов
остаётся отдельным действием, не скрытым успешным fallback внутри Invoke.

До SQL требуются bounded binary, верные ID/разрешение и точный живой родитель.
Сохраняется исходный рабочий контекст/срок, без 30 секунд на всю CLI; прежняя
граница дочитывания локального процесса пять секунд остаётся. После полного
транспорта проверить тот же полный ID/name/running родителя. Nullable-разрешение
копируется до внешних действий. Успешный путь: inspect / один bounded exec
помощника / inspect, без отдельных cp, idle/prune exec и inspect чтения результата.

### Время, не полномочия исполнения

Прежние восемь грубых фаз помощника и строгий parser остаются. Явный result-режим
добавляет `result_prepare` (проверки/размеры после flush) и `result_emit` (заголовки/
потоки и повторные idle/absence), в этом порядке. Отметка result_emit ставится
до записи detail. Десять непрерывных областей с разрешением 10 мс принимает только
новый result-parser/recorder владельца рабочего вызова; planner/legacy требуют
восемь. Неверное/отсутствующее/пустое содержимое detail делает измерение недоступным,
но не меняет допустимый результат ребёнка. Неверный формат/превышение квоты detail
— отказ транспорта. Финальная запись detail/footer — явно неизмеренное собственное
время помощника внутри host exec; две грубые фазы не объявляются точным временем
всего конверта и не складываются с родителем.

Настоящий host `capture.result_decode` охватывает формат/манифест/хеши;
`capture.read` остаётся только для независимого чтения. Campaign/Go/Node заранее
выбирают `same-exec-v1` для точных новых off/on программ, не угадывают 8/10 фаз
по ответу. Старый режим строгий. Исходный API-таймер и аддитивная шкала включают
вызов, декодирование и обе проверки без двойного счёта.

## Новые тесты IR01–IR10

1. **IR01 — точный двоичный формат.** Новые decoder-тесты runtime с независимыми
   буквальными конвертами: пустые/обычные/NUL/non-UTF8 потоки, ребёнок 0/7/255.
   Проверить поля/заголовки/footer/EOF, реальную привязку манифеста и все длины/
   хеши; похожий footer внутри потока не создаёт завершение.
2. **IR02 — отказы/квоты.** Обрезать каждую границу; другой version/order/member,
   повтор/лишнее поле, неканоническая/переполненная длина, manifest8192/8193,
   поток limit/limit+1, detail4096/4097, большой заголовок/конверт, иной footer,
   отсутствие EOF и чужой манифест дают ноль capture/receipt. Малые лимиты вместо
   огромных выделений; закрытое содержимое ошибок не раскрывается.
3. **IR03 — настоящий путь runtime.** Новые соседние тесты требуют inspect /
   один bounded exec точного помощника / inspect, явные mode/cost/prune,
   настроенный Docker binary, копию разрешения и отсутствие команд чтения после
   успеха. Нет возможности/неверная привязка/отмена — до SQL; другой/остановленный/
   переименованный/неясный родитель запрещён. Прежние контекст, квоты и drain.
   Нет экспортированной фабрики receipt и продуктовых переключателей отказов.
4. **IR04 — ребёнок и транспорт.** Manifest7 при transport0 — известная ошибка
   ребёнка. Ошибка транспорта даже с полными на вид байтами, отмена, неполный
   footer и живой ребёнок — неясность: файлы сохраняются, receipt/completion нет,
   архив/SQL автоматически не повторяются. Отдельное последующее независимое
   чтение может восстановить результат без второго CLI.
5. **IR05 — точный prune.** Первый вызов: `none`, receipt отсутствует. Точная
   сохранённая связь/разрешение и `absent` дают прежний typed receipt только
   после обеих проверок родителя и capture. По отдельности менять scope/digest/
   link/footer; изменение вызывающей стороной не перенаправляет receipt.
   Настоящая очередь по-прежнему требует своё сохранённое основание: footer/
   manifest не освобождает место и не разрешает SQL самостоятельно.
6. **IR06 — detail/закрытость/стоимость.** Новые чистые тесты: десять упорядоченных
   непрерывных фаз, точные границы переполнения/квантования, отключённый путь без
   работы, прежние строгие восемь, привязка к владельцу, отказ частичных/поддельных
   данных. Неверная диагностика недоступна, допустимый capture не меняет; квоты
   формата отклоняются по IR02. Сырые потоки/ошибки не попадают в логи/отчёт/API.
   Go/Node выбирают ожидания по программе/режиму и отклоняют другой режим, числа
   фаз и неверные суммы.
7. **IR07 — независимое чтение/legacy.** Все прежние ReadComplete/archive/
   stopped-parent/direct-helper/separate-prune/strict-parser тесты сохраняются.
   Новые сравнивают результат конверта и явного чтения побайтово; остановленный
   родитель не запускается. Нового автоматического восстановления нет.
8. **IR08 — настоящий помощник/runner.** Actions, обычный Linux-пользователь:
   закреплённый помощник возвращает двоичные потоки и код7 в том же родителе.
   Для двоичных потоков/кода7 помощник вызывается напрямую с коротким shell-
   ребёнком, а не с shell-аргументами в InvokeTrackedLiquibaseStep (там всегда
   запускается stock Liquibase). Настоящие JVM/SQL отдельно проверяет IR09.
   Настоящие prune/idle, устойчивые файлы и живой ребёнок достигают нужных границ.
   Потеря ответа сохраняет файлы для независимого чтения; оборачивается настоящий
   транспорт, не подставляется успех SQL. Штатная очистка до fallback; не ноутбук.
9. **IR09 — настоящий prepare.** Actions, три изменения, реальные JVM/SQL/JDBC,
   один runner, точная передача БД, данные кэша и очистка. Один inline-результат
   на изменение; ноль успешных capture.read/cp/отдельных prune. O6 cold/hit
   сохраняется. Допуск вызовов, журнал, state/access и CLI на изменение прежние.
10. **IR10 — регрессии/покрытие/замеры.** Полные engine/client/observer и vet,
    настоящий Linux/race где поддерживается, построчно новые помощники цель100/
    минимум95. После O5–O7 прежние восемь CT13 в Actions с точными программами,
    данными/очисткой, фазами, исходным таймером, соответствием коду и точной суммой.
    Критерий скорости сохраняется.

## Ограниченные правки прежних тестов — отдельное утверждение

- **OT-IR01:** только TestInvokeTrackedLiquibaseStepRequiresCapturedResult:
  inline-конверт; у ошибки ребёнка helper exit0/manifest7. Все три случая/ID/
  аргументы сохраняются. IR04 отдельно требует отказ ошибки транспорта.
- **OT-IR02:** только TestStepHelperCostOwnsActualInvocationAndPreservesResult и
  TestStepHelperCostNeverEntersLogSink: местный binary-конверт и точные числа
  команд, десять допустимых step-фаз. Сохраняются off/on/missing/private/oversized/
  child-failed. Явное смысловое исправление: oversized-формат отклоняет транспорт,
  а не становится успехом через удалённое чтение архива; direct recorder-тесты
  сохраняют невмешательство диагностики. Остальные исходы/закрытость/владельцы/
  ошибки прежние. TestHelperTimerClosedBoundaries не меняется: legacy-ветка
  `cost_emit; exit child_exit` остаётся.
- **OT-IR03:** только положительная подготовка/счётчики
  TestLiquibasePrivatePruneInvocationBinding и его pruneBindingRunner: один
  bounded inline, ноль cp/отдельных probe, точное разрешение один раз. Все
  отрицательные привязки по-прежнему без внешних действий.
- **OT-IR04:** только TestCombinedCapturePruneInvocation через местный адаптер:
  шесть операций заменяются на inspect / apply-result / inspect. Прежние
  combined-read/receipt/negative/cost-boundary подготовки и тесты не меняются.
- **OT-IR05:** только TestMainPathCapturePruneEmptyAuthorityOverridesEnvironment:
  местный inline-ответ и аргументы настоящего bounded-вызова. Сохраняется ровно
  одно пустое разрешение; нет выдуманного основания и общей замены подготовок.
- **OT-IR06:** только TestCostMainPathNamedAttributionDocker: fresh capture.read3→0,
  capture.result_decode=3, ровно planner8/step10 фаз. Кэшированные числа и все
  данные/ID/reuse/SQL/очистка остаются. Прежние Docker-тесты reusable-runner не
  требуют ослабления: их явное независимое чтение сохраняется.
- **OT-IR07:** только applied-эталон complete-cost-boundaries.test.mjs меняет
  capture.read на настоящий result_decode. Все независимые отрицательные проверки
  каждой отсутствующей/чужой границы и остальные операции/числа сохраняются.
- **OT-IR08:** только TestReleasedEngine/collect: заранее выбранный режим точных
  новых программ включает расширенный приёмник до запуска движка; parent передаёт
  выбор Node и очищает наследованные значения у legacy. Хеши, нагрузка, launcher/
  CLI, таймер, сроки, эталоны и очистка прежние.

Любое другое противоречие согласуется отдельно. Этот перечень не разрешает правки
O5, прежних absence/failure/recovery или psql-тестов.

## Критический и повторный разбор

Исправлено: двоичные потоки разделяются длинами; обязательны footer/EOF и
настоящие root idle/prune; child7 не равен transport7; ошибка/квота exec не
превращается в успех скрытым чтением. Разрешение копируется, stopped-путь прежний.
Диагностическое содержимое отделено от квоты конверта; legacy строгий; ожидание
десяти фаз задаётся до ответа, не выбирается по нему. Финальная запись detail/
footer остаётся видимым host-временем, не фиктивной грубой фазой. Нет 30 секунд
на всю CLI и пустых интервалов удалённого чтения.
Shell-подготовка явно отделена от настоящего CLI-вызова, чтобы не повторить
прежнюю ошибку передачи shell-аргументов вместо запуска программы.

Повторный разбор сопоставил инварианты с IR01–IR09, пересчитал предел формата,
проверил устойчивые файлы/запрет повторного вызова, настоящие отрицательные
контроли, три команды, изоляцию старых подготовок, отмену и закрытые отчёты.
Открытых P0–P2 в перечне не найдено. Утверждение/реализация/ускорение не заявляются.
