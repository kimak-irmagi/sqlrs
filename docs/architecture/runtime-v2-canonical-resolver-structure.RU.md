# Каноническое разрешение Runtime v2: устройство компонентов

Состояние: устройство компонентов утверждено @evilguest, 2026-10-01.
Порядок работы описан в [схеме взаимодействия](runtime-v2-canonical-resolver-flow.RU.md).

## Модуль и ответственность

Модуль остаётся по адресу
`github.com/kimak-irmagi/sqlrs/backend/libs/runtime-go`. Версия 0.5.0
меняет существующий пакет `resolver`. Второго реестра, координатора,
хранилища или типа результата не будет. Общая библиотека не зависит от
движка, SQLite, Docker, Git, клиента OCI или СУБД. Проверка и восстановление
канонической идентичности относятся к семантическому ядру; организация
хранения остаётся в `resolver`.

| Компонент | Ответственность |
| --- | --- |
| Кодек идентичности в `runtimev2` | Строго записывает и читает `CanonicalResolvedExtensionIdentity` по заданной `ExtensionIdentitySchema`, сохраняя тип каждого поля. |
| `resolver/framework.go` | Единый результат, поставщики, реестр, координатор, ключ и наблюдаемый итог. |
| `resolver/cache_record.go` | Закрытый формат записи: проверки размера, JSON, ключа и контрольной суммы. |
| `resolver/directory_cache.go` | Каталог, принадлежащий движку; атомарная запись и чтение после перезапуска. |
| `resolver/workspace_file.go` | Перевод существующего образцового поставщика файлов на канонический результат без изменения правил безопасного доступа к файлам. |
| Адаптер SQLite в движке | Новый формат записи в существующей таблице, без изменения схемы БД и основного пути подготовки. |
| Проверки внешнего потребителя | Используют только открытые пакеты подготовленной, затем опубликованной версии модуля. |

## Открытый программный договор

Сохраняем существующие имена вместо параллельного набора интерфейсов. Точное
написание можно уточнить при создании утверждённых проверок; обязательны
следующие отношения типов:

```go
type Resolution struct {
    Identity runtimev2.CanonicalResolvedExtensionIdentity
    Evidence json.RawMessage
}

type Resolver interface {
    Descriptor() Descriptor
    IdentitySchema() runtimev2.ExtensionIdentitySchema
    Normalize(context.Context, Workspace, runtimev2.ExtensionDeclaration) (NormalizedDeclaration, error)
    Resolve(context.Context, Workspace, NormalizedDeclaration) (Resolution, error)
    ValidateResolution(Resolution) error
    Revalidate(context.Context, Workspace, Resolution) (Revalidation, error)
    Acquire(context.Context, Workspace, Resolution) (Artifact, error)
}

type Cache interface {
    Load(context.Context, CacheKey, runtimev2.ExtensionIdentitySchema) (CacheLoad, error)
    Store(context.Context, CacheKey, runtimev2.ExtensionIdentitySchema, Resolution) error
}
```

Реестр один раз сохраняет описание и схему каждого поставщика. Он отвергает
отсутствующие, неверные и повторяющиеся описания и сверяет владельца и вид
схемы с описанием. Координатор передаёт схему выбранного поставщика хранилищу.
Версия правил поставщика участвует в ключе; при изменении приведения описаний,
схемы идентичности или смысла служебных сведений поставщик обязан повысить
эту версию.

Семантическое ядро предоставляет доступ только для чтения к владельцу, виду,
схеме и полям канонической идентичности. Это нужно, чтобы поставщик мог
проверить свой результат и получить соответствующий физический объект.
Возвращаемые списки копируются. Для записи и чтения идентичности ядро даёт
кодек, требующий схему; создать непроверенную идентичность через него нельзя.
При чтении он использует построитель `NewExtensionIdentityBuilder`, проверяет
обязательные поля, каноническое представление и отпечаток. Строковая запись
старого формата не принимается.

## Типизированная запись

Новая версия формата — `sqlrs.resolution-cache.canonical.v1`. Старую
`sqlrs.resolution-cache.v1` текущий декодер отвергает. `CacheRecord`
содержит версию, ключ, отпечаток рабочего каталога, описание поставщика,
приведённое описание расширения, результат и контрольную сумму. Результат
содержит каноническую идентичность и отдельно служебные сведения. Для каждого
поля идентичности записываются имя, тип, правило раскрытия, отпечаток и ровно
одно полное значение: текст, каноническое составное значение или
поставщик/обозначение/версия ссылки на секрет. Ссылка не содержит сам секрет.
При этом для остальных типов хранятся полные значения, в том числе полей с
ограниченным раскрытием. Поставщик не должен помещать в них настоящие
учётные данные. Декодер сверяет определение поля со схемой, значение, отпечаток поля,
каноническое представление всей идентичности и её отпечаток.

Повторяющиеся и неизвестные поля JSON, лишние данные после записи,
отсутствующие обязательные значения, нарушенный порядок полей, превышение
ограничений, неверные описания, ключи, схемы, версии и контрольные суммы
отвергаются. Входные массивы копируются; частичный результат не возвращается.
Повреждённая или несовместимая запись служит наблюдаемой причиной повторного
вычисления. Отмена, отказ в доступе и ошибки ввода-вывода прерывают вызов.
После чтения общих данных поставщик проверяет свои служебные сведения.
Новый результат проверяется до записи. При `CURRENT` меняются только
служебные сведения, и запись завершается до ответа вызывающему коду.

Каталог сохраняет действующие правила доверенного расположения, запрета
ссылок, синхронизации, атомарной замены и ограниченной очистки. Очистка может
проверять общую оболочку, сумму и ключ без восстановления идентичности по
схеме поставщика; неверные и устаревшие записи она пропускает. Адаптер SQLite
меняет методы Go и кодек, но не таблицу. Старые строки считаются
несовместимыми; они не превращаются в попадание в хранилище.

### Точный формат записи версии 0.5.0

Состояние: дополнение о формате утверждено @evilguest, 2026-10-01.

Ниже перечислены все допустимые поля JSON. При записи они идут в указанном
порядке. При чтении неизвестные и повторяющиеся поля отвергаются на всех
уровнях, кроме содержимого `evidence`: его имена и порядок определяет
поставщик, но повторяющиеся имена всё равно запрещены. Неверные байты UTF-8
и непарные суррогаты в строках JSON отвергаются, а не заменяются другими
знаками. Все прочитанные строки должны содержать корректный UTF-8.
Обязательные поля не могут быть `null`;
`evidence` содержит одно значение JSON, отличное от `null`. Поля
идентичности упорядочены по байтам UTF-8 имени и не повторяются. Допускается
не более 4096 полей, 64 уровней вложенности JSON (внешний объект — уровень 1,
каждый вложенный объект или список добавляет уровень) и 4 МиБ на всю запись
до её разбора и выделения памяти. Для составного канонического значения
действуют существующие ограничения глубины, числа узлов и длины строк.

```json
{
  "schema_version": "sqlrs.resolution-cache.canonical.v1",
  "key": "<64 строчных шестнадцатеричных знака>",
  "workspace_scope": "<64 строчных шестнадцатеричных знака>",
  "resolver": {
    "role": "<строка>",
    "owner": "<строка>",
    "kind": "<строка>",
    "specification_schema": "<строка>",
    "semantic_version": "<строка>"
  },
  "normalized_declaration": "<существующий объект описания расширения>",
  "resolution": {
    "identity": {
      "schema_version": "sqlrs.runtime.v2.canonical.v1",
      "provider": "<строка>",
      "kind": "<строка>",
      "identity_schema": "<строка>",
      "fields": ["<типизированные поля по порядку имён>"],
      "canonical_bytes": "<обычный base64 с дополнением>",
      "fingerprint": "sha256:<64 строчных шестнадцатеричных знака>"
    },
    "evidence": "<одно значение JSON поставщика, не null>"
  },
  "checksum": "sha256:<64 строчных шестнадцатеричных знака>"
}
```

Текст в угловых скобках для `normalized_declaration`, `fields` и `evidence`
показывает место значения, а не буквальную строку JSON. Описание расширения
использует уже опубликованный формат для своей роли. У типизированного поля
сначала идут `name`, `kind`, `disclosure`, `commitment`, затем ровно одно из
трёх значений: `text` — строка, в том числе пустая;
`canonical_value` — обычный base64 с дополнением от полного результата
`CanonicalValue.CanonicalBytes()`; `secret_reference` — объект со строками
`provider`, `identifier`, `version` в этом порядке. Тип поля соответственно
`text`, `canonical-value` или `secret-reference`, правило раскрытия —
`public` или `protected`. Отпечаток поля равен `IdentityField.Commitment()`
и заново вычисляется из имени, типа и полного значения. Значение base64
после чтения и повторной записи должно остаться побайтово тем же.
`canonical_bytes` содержит полный результат `CanonicalResolvedExtensionBytes`
в обычном base64 с дополнением, а `fingerprint` — результат
`CanonicalExtensionFingerprint`. Восстановленная по схеме идентичность должна
совпасть с обоими сохранёнными значениями. Контрольная сумма сама по себе
не подтверждает подлинность подмены владельцем доверенного каталога.

Отпечаток рабочей области — SHA-256 от байтов UTF-8 физического пути после
последовательных операций `EvalSymlinks`, `Abs`, `Clean`. Исходные данные для
ключа состоят из обозначения нового формата, 32 байтов отпечатка рабочей
области, роли, владельца, вида, схемы описания и версии правил поставщика,
а затем результата `json.Marshal` от приведённого описания. Перед каждой
частью записывается её длина в байтах как 64-разрядное целое без знака с
наиболее значимым байтом в начале. `key` — строчный шестнадцатеричный SHA-256
от полученной последовательности. От версии 0.2.0 отличается только
обозначение формата внутри исходных данных; прежние записи не используют
новые ключи.

Для контрольной суммы поле `checksum` полностью исключается, а остальные
поля записываются через стандартный `encoding/json.Marshal` языка Go в
указанном порядке и с обычным экранированием HTML-символов. Служебные
сведения поставщика сохраняются как проверенный `json.RawMessage`;
стандартный кодировщик удаляет несущественные пробелы. `checksum` равен
`sha256:` и строчному шестнадцатеричному SHA-256 этих точных байтов.
Кодировщик выпускает такую запись. Декодер принимает лишь целый строго
проверенный объект с совпадающей суммой и верными смысловыми полями.
Неизвестная версия внешней записи даёт `ErrIncompatibleCache` до проверки
контрольной суммы. После правильной внешней суммы неизвестная версия
идентичности тоже даёт `ErrIncompatibleCache`. Неверные данные известной
версии, включая сумму или ключ, дают `ErrCorruptCache`. После общей проверки служебные сведения
проверяет выбранный поставщик. Ошибки отдельного кодека идентичности остаются
ошибками канонической проверки, пока их не обработает хранилище.

## Владение данными и параллельная работа

Канонические идентичности и схемы неизменяемы. Служебные сведения копируются
на границе хранилища и результата. Реестр, координатор, выбор схемы и
описание поставщика существуют в памяти. На диске живут только записи
хранилища и отдельно полученные неизменяемые объекты. Пути рабочего каталога,
места расположения объектов, время и служебные сведения поставщика не входят
в логическую идентичность. Параллельные вызовы могут повторить вычисление;
читатель видит только целую проверенную запись.

Существующий файловый поставщик получает фиксированную схему из проверенного
набора `schemas/sqlrs`. В ней есть одно обязательное открытое текстовое поле
`content.digest`. Функция без параметров выдаёт только эту неизменяемую схему
и не позволяет составлять произвольные схемы. Поставщик строит идентичность
из вычисленного отпечатка. Описание входного файла остаётся прежним.
`Acquire` читает отпечаток из типизированного поля и по-прежнему возвращает
только проверенный неизменяемый объект. Это перевод существующего поставщика,
а не разработка нового семейства поставщиков.

## Выпуск

Запрос на изменение включает описание выпуска 0.5.0 с предупреждением об
изменении интерфейса Go и формата записи. Существующий выпускной процесс
проверяет модульные проверки, покрытие, гонки, краткие проверки случайными
данными, соответствие договору, внешнего потребителя, происхождение и
общедоступное хранилище модулей. Задача #147 завершается только тогда, когда
предварительная и окончательная версии указывают на одно проверенное
изменение после слияния и обе доступны через общедоступное хранилище модулей
и базу контрольных сумм.
