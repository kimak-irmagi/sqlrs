# Устройство аутентификации CLI

[Взаимодействие](cli-auth-flow.RU.md) и [OpenAPI](../api-guides/sqlrs-engine.openapi.yaml)
определяют единственный контракт серверного обмена со схемой discovery версии 2.
Прежний прямой обмен с провайдером заменён без режима совместимости.

## Ответственность компонентов

| Компонент | Ответственность |
| --- | --- |
| CLI `internal/app/auth.go` | Выбор профиля, проверка discovery и доверенных адресов, передача таймаута, согласование адреса организации и безопасный вывод. |
| CLI `internal/app/auth_exchange.go` | Реализация TokenExchanger через HTTP API инсталляции и преобразование безопасных отказов. |
| CLI `internal/client` | Публичные структуры discovery, анонимные JSON-запросы обмена и обновления с ограничением ответа, без лишнего Authorization, повторов и перенаправлений. |
| CLI `internal/authsession` | State, nonce, PKCE, браузер и локальный обработчик, проверки личности, выбор bearer-токена и запись системного хранилища. |
| Сервер | Секреты приложения, обращение к провайдеру, проверка подписей и JWKS; синхронный ответ без постоянного хранения пользовательских токенов. |
| Локальный движок | Прежняя локальная аутентификация, без обмена с внешним провайдером. |

## Интерфейсы и типы

`TokenExchanger.ExchangeCode` и `.Refresh` получают `LoginProvider`: привязку
`InstallationBinding` (идентификатор инсталляции, управляющий адрес, провайдер,
issuer и client ID), адреса операций и таймаут. Запросы содержат только код,
проверочную строку, адрес возврата и nonce либо refresh token, исходные subject
и nonce. Ответ содержит ID token и необязательные refresh/access tokens.
В этих типах, запросах и локальном хранилище секрета приложения нет.

`ProviderRevoker` — отдельная возможность отзыва без секрета. Источник случайных
данных, часы, браузер, локальный обработчик и хранилище подменяются для тестов.
Рабочий менеджер получает явный серверный обменник и не создаёт прямой обменник
провайдера самостоятельно.

Описание провайдера содержит только открытые настройки и серверные адреса обмена
и обновления. Адрес token endpoint провайдера и способ аутентификации приложения
не публикуются. `configuration_version: 2` обозначает фиксированную схему.
Поддерживается адаптер OIDC authorizationCodePKCE. Настройки не могут переопределять
параметры адреса входа, которыми управляет CLI.

## Владение данными

Конфигурация рабочего каталога хранит профиль, маршрутизацию и режим входа,
но не секреты и токены. Ключ системного хранилища включает профиль, постоянный
идентификатор инсталляции и нормализованный управляющий адрес; он не зависит от
организации, провайдера и учётной записи. На всех платформах чтение, запись и
удаление используют один адрес записи. Значение содержит провайдера, issuer,
client ID, subject, nonce, сроки и токены. Успешный вход атомарно заменяет одну
активную сессию; отдельного указателя активного провайдера нет.

Текущий процесс владеет полученными настройками, state, проверочной строкой PKCE,
nonce, локальным обработчиком и временными ответами. Сервер владеет неизменяемой
конфигурацией и разделёнными кешами JWKS. Хранения пользовательских refresh tokens,
выдачи отложенного результата и изменений схемы БД нет.

## Проверки и ошибки

Сервер проверяет подпись и доверенные issuer/audience. CLI проверяет структуру
полученных утверждений и исходную личность. При выдаче результата обе стороны
требуют `exp` строго в будущем. Упреждение обновления не отсекает короткоживущие
действительные токены.

Запись допускается только после успешного входа или обновления. При любом отказе
обновления нет Delete, Put и восстановления ранее прочитанной записи, в том числе
при успехе параллельного процесса. Межпроцессной блокировки не требуется.
Явный выход сохраняет самостоятельное удаление сессии.

Чтение старой конфигурации может обслуживать явное обновление профиля через init,
но неполная сессия требует входа заново. Это не включает схему 1, прямой обмен,
запрос секрета у пользователя или запасной token endpoint. Ошибки discovery
объясняют необходимость исправить настройки или обновить сервер.

`SQLRS_TOKEN` остаётся явной подменой. Status читает только безопасные сведения.
Токены и исходные описания ошибок провайдера не выводятся. Ответ HTTP ограничен
1 МиБ, таймаут операции по умолчанию 30 секунд; повторов и перенаправлений POST нет.
Синтаксис и результаты согласования адресов описаны в
[руководстве](../user-guides/sqlrs-auth.md).
