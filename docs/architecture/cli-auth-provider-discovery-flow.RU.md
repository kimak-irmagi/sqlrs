# Поток обнаружения провайдеров входа в CLI

Статус: поток взаимодействия компонентов утверждён владельцем продукта 2026-10-23.
Согласованный синтаксис CLI описан в
[`../user-guides/sqlrs-auth-providers-proposal.md`](../user-guides/sqlrs-auth-providers-proposal.md),
решение записано в
[`../adr/2026-10-23-cli-auth-provider-list-discovery.md`](../adr/2026-10-23-cli-auth-provider-list-discovery.md).

## Инициализация удалённого подключения

1. Пользователь выполняет `sqlrs init remote <endpoint>` без устаревшего токена.
2. CLI отправляет публичный `GET <endpoint>/v1/connection-info` с существующими
   правилами безопасных перенаправлений и проверки адреса. Он проверяет
   installation, текущий/control endpoint и непустой список провайдеров.
3. CLI атомарно записывает remote profile. Лишь после успешной записи выводит
   человеку ID/имена провайдеров из ответа и подсказку о входе. Dry run сообщает
   о предполагаемых изменениях, не выдавая профиль за готовый к входу.
4. Выбор провайдера и каталог не сохраняются в конфигурации workspace.

## Повторное получение списка

1. Пользователь выполняет `sqlrs auth providers`, при необходимости выбирая
   профиль глобальным флагом `--profile`.
2. CLI разрешает профиль и временное глобальное переопределение `--endpoint`,
   затем отвергает local mode или отсутствующий/некорректный effective remote
   endpoint до сетевого обращения.
3. CLI отправляет публичный `GET <selected profile endpoint>/v1/auth/providers`
   по существующим правилам транспорта. Bearer token, cookie, ID/refresh token
   не прикладываются. Префикс организации сохраняется; существование организации
   и членство в ней из ответа не выводятся.
4. CLI ограничивает ответ 1 MiB и проверяет публичный список провайдеров.
   Человек видит ID/имя в порядке
   ID и подсказку для входа; JSON содержит публичный массив `providers`.
   Результат не кэшируется и не сохраняется.

## Ошибки и граница входа

- Пустой, некорректный или недоступный список даёт ясную ошибку без устаревшего
  резервного списка.
- Local profile отклоняется до HTTP, запуска engine, браузера и credential store.
- `sqlrs auth login` без провайдера остаётся ошибкой с подсказкой выполнить
  `sqlrs auth providers`.
- `sqlrs auth login <provider-id>` по-прежнему напрямую запрашивает актуальные
  детали выбранного провайдера. Вывод списка не разрешает вход и не предоставляет
  членство в организации.
- API сервера, схема БД, доверие gateway и включение новых IdP не меняются.
