# #89: проверки переноса замеров в GitHub Actions

Статус: предложенный перечень после критического и повторного разбора,
2026-11-08; до новых тестов и реализации требуется утверждение пользователя.
Граница — утверждённый [проект Actions](issue89-performance-actions-design.RU.md),
не новое поведение продукта и не программы восстановления/покрытия #170–#174.

## Границы и доказательства

Быстрые воспроизводимые тесты проверяют подготовку, расписание, полноту данных
и ограничения запуска. Они не подтверждают поведение и скорость движков.
Настоящие внешние Linux-бинарники и Docker для пробных и зачётных серий
запускаются только на машине Actions. Новых замеров на ноутбуке не планируется.

Новый стенд размещается в `test/performance/liquibase`, средства подготовки и
отчётов с тестами Node — в `scripts/performance`. Проверки запуска разбирают YAML
и исполняют ограничения на примерах событий, а не ищут правдоподобные слова.
Тесты стенда используют закрытые временные данные и дочерние процессы,
без новых точек подмены в продуктовых пакетах.

В ветке поставки нет получения/полных эталонов публичного MobilityData, а запрос
JHipster в проверках релиза проверяет только базовый успех. Для замеров добавить
отдельные копии полных независимо полученных эталонов с происхождением/лицензией.
Старые проверки релиза не заменять; зависимости от файлов дерева прототипа нет.
Закреплённые версии исходников: JHipster `6b000b5d23a36c45e01472471b84a44fa2464044`
(8 изменений, Liquibase 5.0.3, prod); MobilityData
`ed866e07b9af277ae78305d17e87ea34f4e6674b` (user: 12; main: 102; Liquibase 5.0.4).
Оба проекта общедоступны под Apache-2.0; izess не является входом.

## Окончательный предложенный перечень

Каждая строка — ограниченная группа тестов. Отрицательные случаи должны доходить
до указанной границы и подтверждать отсутствие последующего измерения/успеха.

| ID | Уровень и случаи | Обязательное наблюдение |
| --- | --- | --- |
| PA01 | Быстрые проверки запуска/ограничений: явная метка PR своего репозитория и ручной запуск; другая метка, обычное изменение/PR, чужая копия репозитория, неверные ссылка/SHA; подготовка кандидата и настройки заданий замеров. | Сбор запускают только разрешённые явные события. Собирается точный выбранный SHA вершины, не результат слияния; текст события не вставляется в команды оболочки. Только права чтения, без секретов/сохранённых учётных данных checkout, стандартная Ubuntu 24.04, без платных/собственных исполнителей. Обычное изменение не отменяет текущую серию; на машине только один стенд. |
| PA02 | Проверки подготовки: закреплённые архив/исходники RC7 и сведения извлечённой сборки; чистая ревизия/платформа/хеш кандидата; отсутствующий файл, неверные хеш/ревизия, грязная или чужая платформенная сборка, опасный путь в архиве. | Проверка до исполнения; любой конфликт запрещает запуск, без запасной пересборки v1. Во всех сериях один объявленный бинарник кандидата, не новые сборки уехавшей ветки. Повреждённые загрузка/распаковка не исполняются и не перезаписывают файлы вне своего каталога. |
| PA03 | Проверки подготовки: закреплённые публичные исходники, полные эталоны, установка JDBC в оба пути, точные образы LB/БД, штатные скрипты запуска/ядро; отсутствующий или изменённый вход/зависимость. | Точные коммиты и исходные байты LF, ровно 8/12/102 записи журнала, независимо сохранённые ожидания схемы/идентичности. Получение, проверка и прогрев — до замеров. Одинаковые байты проектного JDBC, согласованные версии/ядро Liquibase; настоящие Java и скрипты запуска записаны без обещания их полного совпадения. Нет приватного репозитория/сетевой зависимости. Используется прежнее разрешение JDBC, не обход проверки. |
| PA04 | Тесты стенда и настоящий пробный Linux-запуск: пути бинарников/скриптов, очищенное окружение, реальные запросы каждого API, точные PID/локальный адрес; отказы запуска/HTTP/конечные ошибки и отмена. | RC7 использует поддерживаемый Linux-запуск на хосте, кандидат — контейнерный контракт. Для обоих перечитывается поддерживаемая настройка снимков копированием; настройки PG/хранилища хоста не попадают в закрытую среду. Ошибка запуска/настройки не даёт зачётной выборки. Ожидание завершается при failed/recovery_required; нет бесконечного опроса и раскрытия тела диагностического ответа. |
| PA05 | Тесты стенда/доказательств: проходы без кэша/с кэшем, несовпадение эталона, порядка/контрольной суммы/схемы, отсутствие доказанного кэша; настоящий пробный запуск и серии всех примеров. | Монотонный интервал от отправки API-запроса до успешного конечного результата одинаков для обоих движков; готовность, загрузки и запросы эталона — вне него. Каждому запуску движка новое хранилище; второй проход использует его же. Проверяются настоящая БД результата, полный упорядоченный журнал и схема, плюс 0 против 8/12/102 настоящих попаданий кэша состояний. Одного HTTP-успеха или числа задач недостаточно. Отдельная подмена идентичности/суммы changeset или ожидания схемы должна приводить к отказу. |
| PA06 | Проверки Docker/счётчиков: начало/дочитывание событий, неверный/оборванный поток и его ошибка, чужие создания, проверка образа против миграций; настоящий пробный запуск. | Учитываются все свои создания в интервале, включая короткоживущие помощники, без обёрток измеряемых команд. Запоздавшие события не теряются, отсутствующая проверка образа не считается нулём. Вызовы миграций/проверки CLI разделены; число JVM по закреплённому скрипту явно названо расчётным. Неточное наблюдение означает неполную выборку, не ускорение. Число контейнеров Windows не навязывается Linux. |
| PA07 | Проверки расписания/полноты на искусственных выборках: чередование, парные контроли, повторная/пропущенная пара, чужие пример/проход/машина/артефакт, неполное подтверждение; сроки и последовательность. | Не менее пяти разных чередующихся пар v1/v2 для каждого примера и прохода, столько же пар v1/v1, всё на одной машине серии. Подтверждение — отдельная новая машина со своим контролем, теми же артефактами/настройками. Нет смешивания машин или Windows/Linux, тихой замены медленной успешной выборки, параллельных замеров и зачёта пробного запуска как пары. Полный сбор не равен выполнению скорости; прежнее правило P01b разбирается отдельно. |
| PA08 | Проверки бюджета/сроков и настоящий пробный запуск: стоимость подготовки/работы/эталона/уборки, нехватка времени, граница, истечение срока/отмена. | Сначала малый пример, затем оба пути пробного запуска всех 102 изменений для оценки крупнейшей серии с контролем. Шестичасовой бюджет включает неизмеряемые накладные расходы и явный запас на уборку/отчёт. Непомещающаяся серия не запускается, сохраняется неполный отчёт и запрашивается новое решение; число пар не сокращается, серия не дробится, мощности не покупаются. Срок процесса наступает до жёсткого срока задания, оставляя время на уборку. Оценка не считается доказательством завершения. |
| PA09 | Проверки уборки: успех, отказ движка/стенда, срок/отмена, ошибка уборки; ресурсы с похожими именами/вне собственного корня. | Штатная остановка, затем ограниченное завершение с ожиданием только своих процессов; удаление только точных проверенных контейнеров/закрытых файлов задания. Нет общей очистки Docker или удаления только по префиксу. Отсутствие проверяется до уборки тестовой среды, способной скрыть утечку. Ошибка уборки запрещает успех сбора; диагностика безопасна. При жёстком выключении VM исполнение finally не гарантируется: неполные данные не засчитываются. |
| PA10 | Проверки отчётов/публикации: успех/отказ, неизвестные вложенные поля и контрольные секреты/DSN/SQL/журналы; неполная серия, срок, несовпадение примера/эталона. | Только разрешённые типизированные поля и отдельный обезличенный каталог отчётов, без масок всего дерева/хранилища/журналов. Нет SQL-вывода, паролей, engine.json или байтов БД в артефактах, итогах Actions и консольной диагностике, включая отказы. Сохраняются идентичности запуска/VM/фазы, артефактов/исходников/зависимостей/образов/снимков, выборки/разброс/счётчики, исходы эталона/уборки. Неполные данные не превращаются в полный сбор или автоматическую приёмку скорости. |
| PA11 | Настоящий явно запущенный удалённый пробный прогон до полных серий. | Опубликованный Linux RC7 и точный кандидат: сначала JHipster, затем оба MobilityData, включая все 102 изменения, без кэша/с кэшем, с независимыми полными эталонами БД, событиями и подтверждённой уборкой. Записаны совместимость, идентичности входов/драйвера/образов, настоящий способ снимков и общие затраты. Быстрые тесты и пробный прогон не закрывают скорость. Если шестичасовой бюджет не подтверждён, остановиться до полных серий и сообщить препятствие. |
| PA12 | Настоящий удалённый протокол и регрессии после проверки бюджета. | Для трёх примеров прежние пять чередующихся пар и столько же контрольных на одной VM серии; независимое подтверждение получает свою VM и контроль. Проходы без кэша/с кэшем раздельны; прежнее правило P01b применяется лишь после проверки полноты/происхождения. Новые быстрые тесты выполняются вместе с прежними проверками загрузки/JDBC/запуска и обычным CI; старые тесты/пороги покрытия не ослабляются. Неполнота, шум/неопределённость или подтверждённое замедление не закрывают #89 и не разрешают слияние. |

## Прежнее правило приёмки и порядок исполнения

P01b сохраняет утверждённое сравнение с настоящим релизом: время, разброс,
вызовы CLI/расчётные JVM, создания контейнеров, платформа, точные исходники,
образы/помощник/драйвер. Сохраняются заранее объявленная граница шума v1/v1
и разбор медианы парных разностей v2−v1. Положительное превышение,
повторившееся в независимом подтверждении, блокирует релиз; положительная
разность внутри шума неопределённа, не успешна. Нет замеров/эталона — нет
приёмки. Этот перечень не вводит другую статистику/калькулятор.
Подтверждение не заимствует контроль с первоначальной VM.

После утверждения: проверить старые тесты на противоречия; написать новые
быстрые проверки, реализовать только согласованные перенос/стенд, выполнить
проверки, затем удалённый пробный запуск. Только подтверждённая осуществимость
позволяет перейти к сохранённому полному сбору. Новых продуктовых/API/изменений
хранения нет. Покрытие новых средств/стенда измеряется отдельно (цель 100%,
минимум 95%); явное исключение
#89 переносит общее покрытие движка в #174, не функциональную/скоростную приёмку.
Дополнительные итерации покрытия по-прежнему подчиняются AGENTS.md.

## Критический разбор, исправления и повторное ревью

1. P1: копия Windows-стенда не проверит Linux. PA02/PA04/PA11 требуют настоящий
   Linux-архив, штатный скрипт, точные адрес и настройки до измерений;
   продуктовый обход совместимости не разрешён.
2. P1: в ветке поставки нет полных эталонов. PA03/PA05 явно добавляют публичные
   закреплённые данные для замеров; короткие проверки и ожидания, полученные
   самим кандидатом, не могут их заменить.
3. P1: сбор смешанных/неполных серий может выглядеть успешным. PA07/PA10
   отвергают чужие идентичности, повторные/пропущенные пары и неполные контроли;
   сбор и прежнее правило приёмки остаются раздельными.
4. P1: малый пример может недооценить большой и накладные расходы. PA08/PA11
   включают настоящий случай из 102 изменений, общие затраты и запас на уборку;
   нет обещания уложиться и скрытого сокращения.
5. P1: диагностика/уборка при отказе могут раскрыть данные или удалить чужое.
   PA09/PA10 проверяют отказы, точное владение и контрольные секреты;
   отсутствие проверяется до уборки тестовой среды, сырые журналы не публикуются.
6. P2: задержка событий и счётчики другой платформы могут дать ложное ускорение.
   PA06 требует дочитанного достоверного потока, явных расчётных счётчиков
   и настоящих Linux-наблюдений вместо переноса итогов Windows.

Повторный разбор проверил начало запуска по метке, неизменность артефактов между
VM, отдельные идентичности контролей/подтверждения, запрет тихой замены выборок,
закрытость при отказах и предел жёсткой остановки. Других P0–P2 в ограниченном
перечне не найдено. Совместимость, бюджет и скорость ещё не доказаны;
этот документ не означает реализации или выполнения тестов.
