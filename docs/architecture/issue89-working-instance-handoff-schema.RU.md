# #89: схема передачи рабочей БД экземпляру

Статус: предложение после критического/повторного разбора; ожидается утверждение.
[Взаимодействие компонентов](issue89-working-instance-handoff-design.RU.md) утверждено.
Изменения продукта, SQL-артефактов и прежних тестов пока не разрешены.

## 1. Минимальное сохраняемое представление

Расширить prepare_liquibase_session_disposals, не добавляя таблицу.
Добавить основание `instance_transferred` и шесть nullable-столбцов TEXT:

| Столбец | Назначение |
| --- | --- |
| handoff_job_id | Точное задание сессии; отложенный FK к prepare_liquibase_job_finalizations(job_id), ON DELETE CASCADE. |
| handoff_instance_id | Неизменяемая историческая ссылка на экземпляр. |
| handoff_state_id | Последнее опубликованное состояние, не исходный вход сессии. |
| handoff_operation_ref | Прежняя операция запуска; её Source не меняется. |
| handoff_runtime_dir | Точный прежний target операции / рабочий каталог экземпляра. |
| handoff_outcome_digest | Точный хеш неизменяемого prepare_success, также authority_ref. |

Повторно использовать session_id, runner_id, db_runtime_id, requested_at и
runner_absent_at. Копия/задание/поколение/исполнение подтверждения выводятся из
неизменяемых сессии и копии; не дублировать их столбцами.

Для нового основания все шесть полей и оба физических ID непустые/nonnull,
хеш — канонический SHA256, db_absent_at и поля незапуска всегда NULL.
Для остальных оснований все шесть полей NULL; прежние правила сохраняются.
CHECK runner_absent_at допускает либо настоящее db_absent_at, либо полностью
привязанную передачу. Это не общее исключение по строковому основанию.
Прежние проверки UTC/точных ID сохраняются. Новые поля идентичности неизменяемы;
меняться однократно может только прежнее runner_absent_at.

Постоянные FK исторических значений к instances/states/операциям не добавляются:
они мешали бы обычному удалению экземпляра/состояния после завершения задания.
Прежняя защита публикации удерживает живую передачу до конечной фиксации;
исторические ссылки проверяются как история, не как нынешние владельцы.

## 2. Атомарные выбор и публикация

Доверенный метод использует прежнее владение соединением и сверку завершения.
Одна транзакция без внешнего ввода-вывода:

1. Повторно проверяет точного остановленного родителя, последний успешный полный
   вызов, итоговый опубликованный курсор/печать, задание/исполнение/образ/идентичность
   и проверенную привязку доступа той же физической БД. Запрещены оставшийся SQL,
   другие активные владельцы, прежний конечный выбор, принятая отмена/выбранная ошибка.
2. Вставляет запись передачи с заданием/хешем будущего завершения. Отложенный FK
   запрещает зафиксировать её без соответствующего исхода.
3. Вставляет точные неизменяемый prepare_success и прежнюю защиту экземпляра,
   затем экземпляр/счётчик использования и завершение prepare_instance, сохраняя
   прежний порядок и отложенный FK защиты публикации.
4. Сверяет полный связанный набор до фиксации. ID БД, target, физическая
   идентичность и операция результата принадлежат той же рабочей копии.
   Source операции равен исходному входу сессии; итоговое состояние равно отдельно
   проверенному последнему курсору. Source не переписывается.

Защиты выбора допускают только ожидающих очистки закрытых владельцев этой точной
переданной сессии; все остальные исключения инвентаризации сохраняются. Намерение
совпадает с заданием/экземпляром/состоянием/хешем передачи, вставляемый экземпляр —
с запуском/каталогом/операцией. Передача вставляется только до выбора в этой
транзакции, не добавляется к старому исходу задним числом. Сверка потерянного ответа
COMMIT сравнивает шесть полей, физические ID, полный исход/защиту, экземпляр/доступ/
операцию, счётчик состояния и завершение задачи. Частичное чтение не даёт успеха.
Прежний порядок выбора исхода не ослабляется.

## 3. Возобновление, закрытая очистка и освобождение

Перед публикацией может потребоваться возобновить остановленную ради снимка БД
после остановки родителя. Расширяются только прежние защиты запроса/готовности
для итогового успешного курсора с остановленным родителем; запрос сохраняется
до возобновления. Обязательны точный последний вызов и отсутствие отмены/ошибки.
Права на session_exec не возникают: остановленный родитель не принимает новый вызов.

Освобождение закрытых ресурсов требует известной зафиксированной связанной
передачи и живой точной защиты экземпляра, а также свежего отсутствия родителя/
вывода, наблюдаемого вне SQLite. Факты отсутствия БД не записываются; удаление БД/
каталога не вызывается. Подтверждение отсутствия закрытого вывода, освобождение
мест, родителя/курсора сессии и логическое освобождение копии сохраняют прежние
однократность/атомарные границы с отдельным точным основанием владения.
Здесь released означает снятие владения задания, не физическое отсутствие БД;
различие сохранено подтверждением передачи. Исторические ID остаются неизменяемыми.

Конечное завершение требует освобождённых закрытых владельцев переданной сессии
и всех остальных прежних условий. Снимается только прежняя защита публикации;
история передачи не меняется. Удаление задания может каскадно удалить конечную
историю; активная передача/закрытые владельцы его блокируют. После завершения
срок жизни экземпляра/состояния не продлевается. Удаление экземпляра остаётся
единственным обычным владельцем удаления переданных запуска/каталога.

## 4. Формат и установка

Версия компонента сессий меняется с 2 на 3; протоколы помощников остаются private/v2.
Канонический SQL и его точный каталог обновляются прежним утверждённым механизмом
единственного источника. Сохраняются новая/актуальная установка и точный переход
с выпущенной исходной схемы; переход с невыпущенного прототипа/промежуточного PR
не добавляется. Неизвестные/неполные/изменённые определения отвергаются до записей,
инвентаризации и работников. Не исправлять v2 молча и не заявлять совместимость
незавершённых заданий. Ожидания версии в старых тестах меняются только после
отдельного разбора/разрешения, не по одному утверждению этой схемы.

## 5. Исправления разбора и повторное ревью

- P1: постоянные FK передачи навсегда закрепили бы экземпляры/состояния.
  Оставлены исторические значения и прежняя ограниченная защита публикации.
- P1: нельзя фиксировать передачу без успеха. Добавлены отложенный FK завершения,
  точные защиты вставки намерения/экземпляра и полная сверка.
- P1: Source прежней операции отличается от итогового состояния. Проверять оба
  значения отдельно; не переписывать происхождение и не ослаблять путь кэша.
- P1: публикации нужно возобновление с остановленным родителем. Добавлен только
  узкий защищённый путь публикации, без нового допуска SQL.
- P1: общее исключение инвентаризации/отсутствия способно удалить живую БД.
  Обязательны полная передача и защита; отсутствие вывода не означает отсутствие БД.
- P2: частично заполненные варианты и неясные версии. Проверки «всё либо ничего»,
  неизменяемая идентичность, точный формат 3 и отказ до записей.

Повторный разбор не выявил дополнительных противоречий P0–P2 уровня схемы.
Тесты и ограниченные правки прежних подготовок будут представлены после утверждения.
