# Преобразование состояния произвольной командой

Статус: API, взаимодействие и устройство компонентов #156 утверждены @evilguest
19 октября 2026 года. [Перечень тестов](runtime-v2-execution-transform-tests.RU.md)
отдельно утверждён позднее в тот же день. Выпуск — отдельная
задача #157; согласование не означает готовность кода или публикации.

## API и объём

В существующий пакет `schemas/sqlrs` добавляется одна атомарная функция:

```go
func BuildExecutionTransform(
    declaration runtimev2.TransformDeclaration,
    extensions runtimev2.ResolvedTransformExtensions,
    observations []runtimev2.OperationalObservation,
) (runtimev2.TransformIdentityComposition, error)
```

Все типы аргументов и результата уже существуют. Не добавляются изменяемый
конструктор, формат результата, исполнитель, публичный HTTP API, CLI или база.
Модуль по-прежнему зависит лишь от стандартной библиотеки. Пример использования
описан в [руководстве](../user-guides/runtime-go-execution-transform.md).

## Контракт

- Фиксированная схема: поставщик `sqlrs`, вид `execution`, идентификатор
  `sqlrs.execution-transform.v1`. Используются прежние область канонического
  преобразования, кодирование и алгоритм хеширования canonical-v1.
- `declaration.Kind` равен `execution`. Обязательное объявление среды выполнения
  указывает владельца `sqlrs.execution` и вид `environment`. Прежние проверки
  объявлений и ограничения размера сохраняются.
- Аргументы и атрибуты пусты: функция не принимает второе описание команды.
  Reference — исходная ссылка или метка, не значимая команда. Наблюдения
  возможностей и переносимости не входят в идентичность и не разрешают запуск
  или повторное использование состояния.
- `extensions.ExecutionEnvironment` обязателен и проходит существующий
  `ParseExecutionEnvironmentIdentity`, включая схему, вложенные правила,
  нормализацию и пределы. Одного совпадения владельца и вида недостаточно.
- Входы связываются по прежним правилам порядка и соответствия объявлений
  результатам через `extension.input.<index>`. Отсутствие, лишние результаты,
  неверные значения и несовпадения дают отказ. Одинаковые значения допустимы в
  разных объявленных позициях; перестановка разных допустимых входов меняет
  идентичность преобразования.
- Описание выполнения связывается через `extension.execution_environment`.
  Поля `sql`, второго списка аргументов/окружения и произвольных полей нет.
- Единственное необязательное служебное поле — `job_id`: владелец `sqlrs`, вид
  `execution`, схема `sqlrs.execution-transform.observation.v1`. Оно не влияет на
  хеш. Неизвестные поля и чужие схемы наблюдений отвергаются; число наблюдений
  ограничено `runtimev2.MaxResolvedFields`.
  Успешное построение сохраняет точные значения и порядок наблюдений, включая
  допустимые повторы, в независимых представлениях прежнего результата.
  Они не очищаются и не отбрасываются; за правильную классификацию служебных
  сведений по-прежнему отвечает вызывающая сторона.
- Ошибка возвращает пустой результат и постоянные код/путь проверки, без
  исходных значений и названий ключей пользователя. Частично собранный объект
  наружу не передаётся.
  Таблица в [перечне тестов](runtime-v2-execution-transform-tests.RU.md) уточняет
  категории формы/значения/предела и закрытые пути; это уточнение по разбору
  утверждено вместе с обновлённым перечнем.
- Прежние PSQL/Docker и проверочные схемы, контрольные примеры и опубликованные
  идентичности не меняются.

## Взаимодействие и ответственность

Вызывающая сторона сначала разрешает входы и создаёт либо проверяет существующее
описание выполнения. `schemas/sqlrs/execution_transform.go` проверяет правила
новой функции, создаёт закрытую фиксированную схему через `schemaauthor` и
передаёт данные прежним `NewTransformIdentityBuilder`, `BindExtensions`,
`AddObservation` и `Build`. Своего кодировщика или хеша нет. `schemaauthor`
импортирует только утверждённый код схемы, не потребитель.

Результат передаётся прежним `NewTransformEnvelope` и `NewDerivedStateEnvelope`
с исходным состоянием. Потребитель сохраняет полные описания выполнения и входов,
на которые ссылаются хеши; ссылка не заменяет содержимое. Контракты результата
разрешения и кэша прежние. Функция не получает ресурсы, не запускает команды,
не читает пути и не разрешает повторное использование.

Все временные данные принадлежат одному вызову. Нет постоянных записей,
общего реестра, фоновых задач или миграции схемы хранения.

## Граница выпуска

#156 содержит код, документацию и согласованные тесты. После слияния и успешного
CI исходников #157 использует прежний ручной `release-runtime-go.yml` с точным
проверенным коммитом `main`. Выбирается свободная версия модуля, проверяется RC
и новый внешний пример построения преобразования и цепочки состояний, затем
выпускается окончательная версия из того же Go-кода. Прежние теги не меняются;
подмена зависимости через `replace` и PR только ради версии не нужны.
Отдельное рабочее дерево для выпуска не требуется. Изменять workflow выпуска
не планируется. Обёртка из исходного коммита во время прежнего запуска всего
набора обязательно вызывает дочернюю команду только с новым самодостаточным
файлом тестов; есть допустимый и ошибочный контроль изоляции. Прежнее копирование
`*_test.go` включает оба файла до выпуска, для RC и окончательной версии,
не подставляя тесты H вместо тестов исторического S. Точный порядок задан в ET08.
